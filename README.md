# Trade Side

Tools for interior designers working with vendors to the trade. The first tool files resale certificates:

1. Paste a vendor's website.
2. The app reads the vendor's site, finds their trade program and how they want certificates (email, online form, account sign-up, or a rep).
3. It fills in and signs the California resale certificate (CDTFA-230) for that vendor.
4. It files it: an email to the vendor sent from Trade Side under the firm's name (replies go to the designer, who gets a copy), an optional draft in the designer's own Outlook, or a cloud browser that fills the vendor's online application and stops for them to review and submit.
5. The vendor list shows who you've filed with, when, and how, so nothing gets filed twice.

The second tool keeps one record per product a firm is specifying:

1. Paste the link to a product page.
2. The app reads the name, maker, SKU, dimensions, material, finish, lead time, photos and price.
3. It applies the firm's discount and markup with that vendor, and passes freight through at cost.
4. The item page gives one description block to paste into a proposal, and shows whether a certificate is on file with the seller.

Workspaces are multi-tenant and self-serve: any firm signs up, creates its workspace and invites its team. Each firm has its own members, certificate details, documents and vendor list.

## Stack

- Next.js 16 (App Router, server actions, `after()` for background work) on Vercel
- Supabase: Postgres with row-level security, magic-link auth, private storage
- Anthropic (Claude) for reading vendor sites; Firecrawl for crawling them
- pdf-lib for filling the official state PDF
- Resend for all email (sign-in links, invites, certificates)
- Microsoft Graph for optional Outlook drafts
- Browserbase + Stagehand for filling vendor web forms

## Layout

| Path | What it is |
| --- | --- |
| `supabase/migrations/0001_init.sql` | Schema, RLS policies, storage bucket |
| `forms/` + `src/lib/forms/` | Official state PDFs and the registry that fills them. Add a state here. |
| `supabase/migrations/0003_items.sql` | Projects, items and each vendor's discount and markup |
| `src/lib/research.ts` | Vendor site crawl and extraction |
| `src/lib/clip.ts` + `src/lib/product-data.ts` | Reads one product page into an item. `product-data.ts` is the exact part (the page's own markup), with no network or model |
| `src/lib/items.ts` | Item rules: how a price is worked out, what an item is missing, the proposal description |
| `src/lib/firecrawl.ts` | The one Firecrawl client, shared by research and clipping |
| `src/lib/jobs/` | Background jobs: research, item clipping and online-form filling |
| `src/lib/outlook.ts` | Outlook connection, drafts, sent detection |
| `src/app/actions.ts` | Server actions for the whole app |
| `src/app/(app)/` | Signed-in pages: vendors, vendor detail, items, item detail, settings |

## Setup

### 1. Supabase

Create a new Supabase project (keep it separate from other businesses), then run the migration:

```bash
supabase link --project-ref <ref>
supabase db push
```

or paste `supabase/migrations/0001_init.sql` into the SQL editor.

In **Authentication > URL Configuration**, set the Site URL to `https://www.thetradeside.com`. Sign-in links are generated by the app and emailed through Resend, so Supabase's own email sending isn't used.

### 2. Email (Resend)

Create a Resend account for Trade Side, add and verify the `thetradeside.com` domain (Resend gives you the DNS records), and set `RESEND_API_KEY`. Mail goes out as `signin@`, `hello@` and `certificates@thetradeside.com`.

### 3. Microsoft (optional Outlook drafts)

In the [Entra admin center](https://entra.microsoft.com) > App registrations > New registration:

- Supported account types: **Accounts in any organizational directory and personal Microsoft accounts**
- Redirect URI (Web): `https://thetradeside.com/api/outlook/callback`
- API permissions (Microsoft Graph, delegated): `offline_access`, `openid`, `email`, `User.Read`, `Mail.ReadWrite`
- Certificates & secrets: create a client secret

Copy the Application (client) ID and secret into `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET`. If a firm's Microsoft 365 is managed by IT or GoDaddy, an admin may need to approve the app the first time.

The app only ever creates drafts. It never sends email.

### 4. API keys

- `ANTHROPIC_API_KEY` from console.anthropic.com
- `FIRECRAWL_API_KEY` from firecrawl.dev
- `BROWSERBASE_API_KEY` and `BROWSERBASE_PROJECT_ID` from browserbase.com (optional; the online-form option stays hidden without them)

### 5. Environment

Copy `.env.example` to `.env.local` for local work, and set the same variables in Vercel. Generate the two secrets with `openssl rand -base64 32`.

Signup is open by default: anyone can create a workspace for their firm. Set `SIGNUP_MODE=invite` to limit sign-in to invited emails plus `BOOTSTRAP_OWNER_EMAILS`.

The sign-in form is the one form anyone can submit, so it carries a Cloudflare Turnstile check that stops scripts from requesting sign-in links for addresses that never asked. Create a Turnstile widget for `thetradeside.com` in the Cloudflare dashboard, then set `NEXT_PUBLIC_TURNSTILE_SITE_KEY` and `TURNSTILE_SECRET_KEY`. The check is off until both are set.

### 6. Run

```bash
npm install
npm run dev
```

## Browser extension

`extension/` is a small Chrome extension that adds the page a designer has open
to Trade Side. It exists because a vendor's trade price only shows after
sign-in, where the server can't read it. On a pin it follows the pin to the
page it came from.

To try it: open `chrome://extensions`, turn on Developer mode, press Load
unpacked and pick the `extension` folder. It talks to www.thetradeside.com. To
point it at a local or preview build, open Settings in its popup and enter that
address (Chrome asks before allowing it).

It posts the page address and a trimmed copy of the page source to
`/api/clip`, using the designer's own Trade Side sign-in. It reads a tab only
when clicked there. It never types into a page, presses a button, submits a
form, fills a password or solves a verification check, and text boxes are
removed from the copy before it is sent. The page source is read once and not
stored.

## How filing stays safe

- Certificates are signed only with the signature the signer drew, typed or uploaded themselves.
- Certificates are emailed only when a designer presses Send to vendor (or Send in their own Outlook for drafts). Replies go to the designer.
- The online-form assistant never submits, never types passwords and never solves verification checks. It hands over to a person in a live view.
- Outlook tokens are encrypted at rest; storage is private and read only by the server after a workspace check.

## Adding a state

Add the official PDF under `forms/<state>/`, then add an entry to `FORMS` in `src/lib/forms/index.ts` mapping its field names. `scripts/test-fill.mts` fills a sample certificate for a visual check:

```bash
npx tsx --conditions=react-server scripts/test-fill.mts signature.png out.pdf
```
